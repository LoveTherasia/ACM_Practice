## 简单题骨架

典型 `solve()` 只有 5–16 行，输入读取往往就占了答案的一半。观察到的固定节奏：

1. **读入直接落到下标范围**：`for(int i=1;i<=n;i++) cin>>a[i];`
2. **一到两层循环做统计 / 贪心**，累加进 `int res = 0;`
3. **末尾一次输出** `cout<<res<<"\n";`

实例（均为实测）：

| 题目 | 骨架 | 体量 |
|---|---|---|
| `nowcoder\113313\B` | 读 `n` → 直接输出四个闭式表达式 | `solve()` **7 行** |
| `nowcoder\113313\A` | 读 `double x` → `cout<<fixed<<setprecision(10)<<150.0*log(x);` | 5 行 |
| `AtCoder\abc_416\B` | 读字符串 → 扫描翻转首个 `.` → 输出 `s` | 15 行 |
| `AtCoder\abc_416\A` | 读 `n,l,r` + 串 → `s = 'a' + s` 转 1-based → 区间内查 `'x'` | 16 行 |
| `AtCoder\abc_416\C` | 读 `n,k,x` → `dfs(1)` 枚举长为 k 的串 → `sort` → 取第 `x` 个 | 12 行 + helper |
| `codeforces\1037\B` | 统计 0 的后缀个数 `num[i] += num[i + 1]` → 前向贪心跳 k | ~12 行 |
| `codeforces\1037\C` | 把 `a[i] > a[k]` 压进 `priority_queue<...,greater<>>` → 模拟爬升 | ~20 行 |
| `codeforces\1027\E` | 读边建链式前向星 → `dfs(1,0)` 树形 DP → 空格分隔输出 | ~30 行含 helper |

## 简单题共性

- **串转 1-based 是个小技巧**：读进来后 `s = 'a' + s;`，之后就能用 `s[l]..s[r]` 直接下标，不必到处写 `s[i-1]`。
- **提前退出而非标志位**：`cout<<"No\n"; return ;`（`abc_416\A`）、`cout<<"NO\n"; return ;`（`1037\C`）。大小写跟随题面，没有统一house style。
- **`res` 是标准累加器**；`cnt` 在这些简单题里**一次都没出现**。
- **容器用得很少**：这 8 个文件里只出现了 `priority_queue`、`deque`、`vector<string>`；**没有 `map` / `set`**。全库 `vector<int>` 也只占 11.9%。
- **没有经典前缀和**：`1037\B` 用的是后缀计数数组，`1027\E` 用的是 DP 的 `pre[]`。全库 `pre[]`/`sum[]` 形态占 7.7%。
- **零解释性注释**。8 个文件里唯一的注释是一条被注掉的调试：`//cout<<x<<" "<<fa<<" "<<dp[x]<<" "<<pre[x]<<"\n";`
- **浮点输出**：`cout<<fixed<<setprecision(10)` —— 精度开到 10 位。
- **模板里的 `rng`/`Base` 照抄但不使用**，`#define ull` 在 2025 年那批里也没有（该批已过时）。

## 排序与比较器（137 个文件用 sort）

调用形态按全库出现次数排：

| 形态 | 次数 | 说明 |
|---|---|---|
| `sort(a+1,a+n+1)` | 28 | **主导形态**：全局数组 1..n 升序 |
| `sort(a + 1,a + n + 1)` | 11 | 同一写法的带空格变体 |
| `sort(v.begin(),v.end())` | 12 | vector 升序 |
| `sort(b+1,b+n+1)` / `sort(p+1,p+n+1)` / `sort(node + 1,node + q + 1)` | 各 3–7 | 换数组名，形态不变 |

- **降序第三参写 `greater<int>()`**（23 个文件）。
- **lambda 全库 0 次、`bool cmp(` 只有 2 个文件**——要自定义顺序就给 struct 写成员 `operator <`（21 个文件；`struct Node` 24 个）：

```cpp
struct Node{ int l; int r; int idx; bool operator < (const Node &other){ return this->l < other.l; } }node[N];
// 之后 sort(node + 1,node + n + 1);
```

- **结构化绑定 `auto [` 已落地 70 个文件**，是活跃习惯。高频形态：`auto [x,y] = p[i];`（9 次）、`auto [x,y] = q.front();`（网格 BFS，5 次）、`auto [dis,pos] = q.top();` / `auto [cost,pos] = q.top();`（Dijkstra）。
- range-for `for(auto ...)` 45 个文件，主要遍历 `map` / `vector`。
- `__int128` 仅 3 个文件，日常题不写（见数论节）。

## 前缀和（35 个文件）

- 一维形态**在读入循环里顺手算**，或紧跟一条独立循环：

```cpp
for(int i=1;i<=n;i++){
    cin>>a[i];
    pre[i] = pre[i - 1] + a[i];
}
```

- 命名：`pre[]` 前缀、`bac[]` 后缀、`sum[]`（18 个文件，更多出现在线段树 / 分块）。
- 查询直接写 `pre[r] - pre[l - 1]`，不抽函数。
- 简单题里比经典前缀和数组更常见的其实是**后缀计数数组**：`num[i] += num[i + 1];`（如 `codeforces\1037\B`）。

## 字符串处理

- **一律 `string`**：`string s` 出现在 178 个文件；`char s[N]` 全库 **0** 个文件。`getline` 只有 2 个文件——默认整词 `cin>>s`。
- **1-based 下标技巧**：读入后 `s = 'a' + s;`，之后直接用 `s[l]..s[r]`（2 个文件）。
- 字符串算法极少独立成板：KMP 用 `nxt[]`（5 个文件，如 `codeforces\1060D.cpp`）；Manacher 模板在 `Luogu\P3805-马拉车模板.cpp`；trie 是 `son[N][26]` 式数组（2 个文件）。
- `to_string` / `stoi` 全库仅 1 个文件——拆数字一律 `while(x){ ... x /= 10; }`。

## 无穷大与模数

| 用途 | 规范形式 | 文件数 |
|---|---|---|
| 整型无穷大 | `MOD * MOD` | **73**（标准） |
| 备选 | `1e18` | 15 |

| 模数默认 | `const int MOD=1e9 + 7;` | 1082 |

## 多测与重置纪律

- 行首活跃的 `cin>>t;` 530 个文件，注释掉的 `//cin>>t;` 544 个——**接近一半一半；单测也要保留注释行**。
- **`memset` 全库只有 23 个文件**，大头是数位 DP 在 `count(x)` 里显式清表。
- 多测 + 全局状态时的实际重置方式是**循环重赋值覆盖**：`for(...) vis[i] = 0;`（14 个文件）、`dist[i] = MOD * MOD;`（每轮读入时重赋），或把每轮计数变量放局部。
- 最常见的姿态反而是：**状态全局、按单测写**（注释 `cin>>t;`）——竞赛代码不为多轮残留负责。生成多测题解时，优先确认"这套全局状态在第二轮会不会脏"，会脏就把重置写进 `solve()` 开头。

### 不给组数的题：EOF / 哨兵读入（4 + 1 个文件）

洛谷模板题和 HDU 老题常不给数据组数，两种读法都有实例：

```cpp
// EOF 读入：while(cin>>s)（Luogu\P3805-马拉车模板.cpp）
while(cin>>s){ ... }

// 哨兵终止：while(true) + 全零退出（algorithm\SG函数计算\HDU-1848.cpp）
while(true){
    int n,m,p;
    cin>>n>>m>>p;
    if(n==0 && m==0 && p==0) break;
    ...
}
```

- 优先 `while(cin>>...)`；只有当"合法输入也可能全零"时才用哨兵。
- 斜率优化板子的多测不走 `main` 的 t 循环，而是在 `solve()` 内 `while(cin>>n){ cin>>m; ... }`（见 `dp.md`）。
- 这类文件 `main` 里保持 `int t=1; //cin>>t;` 原样——EOF 循环写在 `solve()` 内或替代 t 循环，模板外壳不动。

## 数论

`一些板子集合\数论\` 只有 3 个文件，且**性质各不相同**，不能当作统一范式：

### 非质模数意义下的乘法逆元（唯一规范的作者模板）

在模板三件套之后追加两个 helper：

```cpp
static inline int exgcd(int a,int b,int &x,int &y)
static inline int modInverse(int a,int m)
```

- `modInverse` 在 `g != 1` 时返回 `-1`，否则 `(x % m + m) % m`
- `static inline` 是作者自己的写法，只在模板文件里出现
- 该文件把 `#define lowbit(x)` 写成了带括号的 `(x&(-x))`，并加了 `#define ull` —— 属于**提前采用 2026 模板**的文件
- `solve()` 只有 3 行：`cin>>x>>y; cout<<modInverse(x,y)<<"\n";`

### 米勒-拉宾素性检验（外部片段，非作者风格）

⚠️ **不要把这个文件当作风格样本**：无 ASCII 头、无 `#include`、无 `main`、无 `using namespace std;`、无 `#define int long long`，Allman 大括号，中文注释（`// 快速幂`、`// 注意！中间结果可能溢出…`）。整份是贴进来的外部代码。

其中值得保留的只有一点：**全库唯一使用 `__int128` 做溢出保护的地方**：

```cpp
ans = (__int128)ans * a % p;
v = (__int128)v * v % x;
```

确定性基数组 `ll A[] = {2,325,9375,28178,450775,9780504,1795265022}`。

### CF-Edu-Div2-Round-194-B（其实是普通题）

含模板 `qpow`/`inv`/`lcm` 但都是摆设；实际做的是整除分块 + 二分 + 等差数列求和。`MOD` 声明了没用。

### 组合数（fac[] + C(x,y)，非板子目录）

全库只有 1 个文件用 `fac[]`（`CCPC\2024_jinan\F.cpp`，模数改为 `998244353`），但结构可以直接沿用：

```cpp
int fac[N];

int MUL(int x,int y){
    return x * y % MOD;
}

int C(int x,int y){
    return MUL(fac[x],inv(MUL(fac[x - y],fac[y])));
}
```

- 阶乘表 `fac[]` 全局；模板 `inv()` 直接复用；乘法包装成 `MUL`（全库少数全大写的名字，小写 `mul` 也有 16 处）。
- ⚠️ 该文件是**草稿态**：循环里留着活的调试输出 `cout<<"初始"<<ans<<"\n";`、甚至有空 `for` 体——不要模仿；要抄的只有 `fac[]/MUL/C` 的结构。

## 数论写法的三条实际约定

1. **作者的模逆路径是 `exgcd`，不是快速幂。** 快速幂 `inv()` 是模板自带的（默认模数 `1e9+7`），一旦模数运行时才给定，就切到 `exgcd`。
2. **溢出保护只有 `__int128`**，没有快速乘。且只在米勒-拉宾里出现过；日常题不写。
3. **模板 `qpow`/`inv`/`lcm` 即便用不到也保留**，这是全库惯例而非疏漏。

## 偏差提醒

- `一些板子集合\数论\` 一半是外部代码，抄算法可以，抄外框不行。
- 米勒-拉宾那个文件只有 46 行且**没有 ASCII 头**，用 `-Skip 42` 读会把代码整个吃掉。读任何板子文件前先判断前 42 行是否全为 `//` 或空行。
- **带壳的异样正文（2026-10 新出现）**：`nowcoder\2026国庆第四场\I.cpp` 有标准艺术头，但正文是另一种风格——`#include <bits/stdc++.h>`（带空格）、`cin >> n`（带空格）、大段中文解释性注释、0-based 循环、局部 `vector` 存图。属于套了壳的外部/AI 生成正文。**头的存在不等于风格合规**；评审以正文为准，写新代码也不要把这类文件当成可接受变体。

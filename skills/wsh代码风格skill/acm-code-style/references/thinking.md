# 思路历程：拿到题之后怎么想

本文件提炼作者本人的解题推理过程，语料是作者手写的思路笔记（`codeforces\汇总清单.md`、`nowcoder\总结清单.md`、`nowcoder\每日打卡\总结清单.md`、`ICPC\总结清单.md`、根目录 `汇总题单.md`、`一些板子集合\一些trick\数学技巧.md`）。目标：让 AI 按同样的顺序问同样的问题，得出同一路线的解法。

## 第 0 步 —— 固定思考流程（六步）

1. **读题找信号**：题面元素 → 算法族（见 §1 信号表）。
2. **数据范围定复杂度**：n 的范围 → 预算出能用的算法档位（见 §2）。
3. **走该算法族的思考剧本**（见 §3），从剧本第一个问题开始问。剧本问不通时查 `approach-library.md` 的元策略（条件拆分、代数变形找熟悉式子、仿写模板变体等）与题型做法条目。
4. **结论落到骨架**：按 `SKILL.md` 路由到对应 topic 文件，套观察到的代码形态。
5. **验证**：样例 → 手搓边界小例 → 需要时对拍（见 §5）。
6. **收尾清单**：`SKILL.md` 第 7 步的 15 项。

作者笔记里反复出现的口头禅是思维触发点的线索："很容易发现 / 不难想到 / 很典的 / 没什么好说的"——**这些句子出现的地方都是标准套路**。如果一道题你想不出且题面命中 §1 的某个信号，先回头查套路表，不要自由发挥。

## §1 题面信号 → 算法族（作者自己的联想路径）

作者笔记原话佐证了每条联想：

| 题面信号 | → 想到 | 证据 |
| --- | --- | --- |

| "连续的 0 的段" / 分段结构 | 只看段，组合数 / 隔板法 | "很容易发现的一点是我们只需要看连续 0 的段"（每日 2026-01-29） |

| 排列 + 相邻交换代价 | 交换论证得比较键 | "S*c1+(S+w1)*c2 > S*c2+(S+w2)*c1，简化得到 w1/c1 > w2/c2"（网络赛第二场 J） |

| 递推会重复计算同一子问题 | 记忆化 / DP | "用 dp[i] 表示以 Cwbc 中第 i 个位置结尾的子序列个数就好了……挺典的"（每日 2026-02-02） |

| 总和整除结构 | 答案只能是 n 或 n-1 | "如果总和 sum 能够被 n 整除那么众数最大数量就是 n，否则就是 n-1"（每日 2026-02-03） |

## §2 数据范围 → 复杂度预算

| 范围 | 预算 | 本库常见落点 |
| --- | --- | --- |
| ≤ 20 | 指数级可过 | 状压 DP（`dp[1<<16]`、`dp[1<<18]`）、折半搜索 |
| ≤ 500 | n³ | 区间 DP `dp[505][505]` 三层 |
| ≤ 2000 | n² | 二维网格 `char a[505][505]`、`dp[110][110][110]` |
| ≤ 1e5 | n log n | 线段树 / 树剖 / 二分 + check |
| ≤ 1e6 | 线性 | 前缀和 / 贪心扫描；数组直接开 `N=1e6+10` |
| 1e18 | O(log) 或**结论** | "范围是 1e18，而 2 的 60 次方就已经大于 1e18，所以如果 k>60 的话就肯定直接输出 1"（每日 2026-02-04）——先想指数上界特判，再想二分 |

`N=1e6+10` 是模板默认值这一事实本身就是一个提示：作者按"大多数题 n ≤ 1e6"准备，**超过 1e6 才需要改 N**。

## §3 各算法族思考剧本

### 3.1 贪心

依次问：

1. **排序后每一步取什么？** 大多数贪心题答案 = 排序 + 一层扫描（58% 的题本来就是简单题）。
2. **要不要交换？→ 交换论证**：设相邻两个元素 1、2，比较"1 在前"和"2 在前"的总代价，化简成不等式就得到比较键。作者原例：`S*c1+(S+w1)*c2 > S*c2+(S+w2)*c1 ⇒ w1/c1 > w2/c2`（网络赛 J）。
3. **贡献被区间覆盖？→ 谁被包含得最多改谁**："一个糖果可以在多个连续 m 个盒子区间中……我们要修改被最多可能需要修改的区间包含的位置，也就是最右边的位置"（每日 2026-02-07）。从左到右滑动窗口，优先动最右。
4. **取值只依赖两端？→ 后缀最大值 / 两端差值**："聚焦于和每个数字差值最大的数字，那就是两端的值"（1077-Div2 C）；"直接取后缀最大值数组然后前缀和差分进行区间求和"（1076 C）。
5. **每步检查不可行条件**（数量不能为负、两边都有 1 的边界——每日 2026-02-07 与 1077 B 都强调过）。

### 3.2 数学 / 组合计数

1. **先找整除 / 平均值结构**：答案常常只有两三种取值（n 或 n-1，每日 2026-02-03）。
2. **"恰好"约束 → 拆步计数**：把"恰好一半"拆成"选出来 × 放进去"的乘积再求和——2026-02-01 拆成了 4 步：①从 3 的倍数里选出若干个 ②有序放到 3 的倍数位置 ③非 3 倍数补剩余倍数位 ④剩余数字填满剩余位置。
3. **段内分配 → 隔板法**：连续 0 段 [l,r] 内放 i 个数字 = `C(可选数字数, i) × C(i, 段长)`，两组合相乘、各段相乘（每日 2026-02-29 全过程）。
4. **递推会算重 / 算不动 → 概率或闭式**：区间覆盖概率题里"前缀和包含了选中区间，所以要除以不出现的概率消除影响"（`汇总题单.md` Education_181 D）。
5. **结论题看结构不变量**：前后缀 gcd 题——"数组肯定只会不断变小，每次变小只会变成因数，所以前后有整除关系；a[n] 和 b[1] 都表示全部数字的 gcd，所以这两个值要相等"（`汇总题单.md` 1037E）。
6. **小公式库**（`一些trick\数学技巧.md`）：因子个数 = ∏(eᵢ+1)；1,11,111… = (10ⁱ−1)/9。

### 3.3 构造

1. **先钉死特殊位置**："对于 i=n-1，我们必须让倒数两个位置放 1 和 n，然后最后往前根据差模拟"（1077 A）。
2. **保持已构造部分不破坏，逐步扩展**："唯一的难点在于我们需要维持我们原有已经排好的顺序"，用两种操作循环把已排好序列挪到后面（重庆热身赛 C）。
3. **环 / 旋转 → 化成前缀和最值条件**：n 次旋转合法 ⇔ "pre[k-1] 是后面的前缀和中最小" + "最小前缀和加上 pre[n]-pre[k-1] ≥ 0"（`汇总题单.md` 2025_Hunan D）。
4. **无解条件 = 存在"进得去出不来"的陷进**：视野限制题里"从终点跑一遍 BFS，找终点到不了、起点能到的连通块，长度 ≥ k 就会被困"（`汇总题单.md` 108301B）。

### 3.4 DP

1. **定状态只问一句**："什么信息是转移时必须记住的？" 主流答案按题面给：以 i 结尾（`dp[i]`）、前 i 位已处理（`dp[i]`）、(位置, 附加维)。
2. **树上**：回归时逐子树合并（"dfs 回归的时候对每个分支进行最小值运算之后累加"，每日 2026-03-07）；需要换根就 `dfs1` 自底向上 + `dfs2` 自顶向下（`dp.md`）。
3. **区间**：长度外层、断点内层（`dp.md` 固定三层）。
4. **带修改的历史依赖 → 先推朴素递推式，再矩阵化**：先手动推 `dp[i] = max(dp[i-1]+1, num[i])`，"有 q 次修改又不能每次遍历，所以用矩阵存储区间信息，线段树存每个区间的矩阵"（`汇总题单.md` 108303G）——**顺序是先有递推式，才有矩阵加速**。
5. **数位**：固定四参数 `dfs(pos, 前驱状态, 前导零 st, 限制 limit)`，记忆化只在 `!limit && !st` 时存（`dp.md`）。

### 3.5 位运算 / 思维题

1. **最高位优先**：比较类结论先看最高位——"ai & aj >= ai ^ aj 当且仅当最高位相同"（`汇总题单.md` 672B）；构造位运算操作时"核心就在于首先让 a 和 b 最高位一致"（108300B）。
2. **分段思考**：把相邻操作看成段，"如果有奇数个段就相当于一段……偶数个段可以分为两个奇数段"（每日 2026-02-11）。
3. **打表找规律**：异或路径题"根据这个结果我们可以进行打表发现规律直接用就好"（每日 2026-01-28）。
4. **无限过程 → 找不变量 / 不动点**：坐标变换无限次 ⇔ 每次都是自身或 (x,y)↔(y,x)，然后对第二种情况代入异或恒等式逐个证伪（每日 2026-02-21）。

### 3.6 博弈

1. **先打表再命名结论**：昆明 D 把局面按"不在位置的数字个数"分三类逐个推；巴什博弈打表得 `n%(m+1)==0` 后手胜。
2. ** Nim 型 → SG 值异或和**（`misc-algorithms.md` 的 mex 三步）。
3. 结论要能反推操作：'后手总能选一个数让两个人选的数和为 m+1'（每日 2026-02-06）。

### 3.7 图论

1. **树**：答案 = 子树信息合并或换根（§1 前两条）。
2. **最短路 + 点权 / 多源 → 虚拟节点**：abc_463E 新建节点 `n+1`，把点权变成边权 `add(i,n+1,2*a[i]+y)`——**把"额外代价"建模成边是作者的标准手法**。
3. **连通判定 → BFS**；网格上状态数 = 格子 × 状态，直接 `dis[x][y][st]`。
4. **表达式型建图（2-SAT）→ 位移技巧镜像边**（`graph-and-basic.md`）。

### 3.8 数据结构选型（一句话决策树）

单点改 + 前缀和查 → 树状数组；区间改 + 区间查 → 线段树懒标记；历史版本 / 第 k → 主席树；离线区间统计 → 莫队；带修改的线性递推 → 矩阵 + 线段树；区间 gcd / 区间合并信息 → 线段树 `push_up`（`data-structures.md`）。

## §4 作者的思维习惯（写题解说明时的口吻）

- **先说"很容易发现"的那一句**——题解式推理从最平凡的观察开始，逐步推进；笔记里每道题的第一句话几乎都是观察而非算法名。
- **第一想法有反例就重新表述**："那么我们换一种想法，从第一个区间出发……"（每日 2026-02-07 整段就是两次修正后的结论）。
- **自省"想复杂了"**：2026-02-03 开头承认"最开始想复杂了导致没想到一个很简单的地方"——简单观察优先于精巧构造。
- **溢出防护是思考的一部分**："为了防止这个计算溢出，所以要改写为 res > 2*n/num"——把乘法比较改写为除法比较（每日 2026-02-04）。
- **特判清单**：四舍五入（2026-01-31）、全负数（2026-03-13）、"剩下不多于三个"的尾段（2026-03-14）、`minvalue <= 1` 早退（同余最短路）。写完主体后主动过一遍这些位置。

## §5 验证与调试剧本

- **顺序**：样例全过 → 手搓 n=1/2、全相同、全递增等边界 → 还不放心就对拍。
- **对拍三件套**（`.dsh\scratch\` 工作流）：`body.cpp`（正解骨架）+ `brute.cpp`（**按定义模拟**的暴力，注释第一行写"暴力：每个询问直接模拟，按定义统计"）+ `search.cpp`（探索小空间内性质的小脚本）。暴力不追求效率，只追求定义正确。
- **打表**：博弈、位运算、规律题先打表（§3.5/3.6）。
- **调试输出**：临时 `cout` 注释保留在代码里（`//cout<<...<<"\n";`），不删除。
- **方向数组注释**：网格题给 `dx/dy` 标注释 `//0上 1下 2左 3右`——方向语义必须注释，这是解释性注释被接受的第二个例外。

## §6 思路层面的反模式

- **过度设计**。58% 的题没有任何高级算法特征；剧本问完前两问就能解决的题，不要引入线段树。
- **硬推有反例的第一想法**。按 2026-02-07 的先例：重新表述问题，而不是修补证法。
- **忽略操作顺序**：涉及"每次操作影响后续"的题（2026-02-07 的糖果盒），先确认贪心顺序不可交换再动笔。
- **先写矩阵/线段树后找递推**。顺序必须是：朴素式 → 发现修改需求 → 数据结构加速。
- **把暴力写成"另一个优化解"**。对拍用的暴力必须按定义直写，否则失去参照价值。

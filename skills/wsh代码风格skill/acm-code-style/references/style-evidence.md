# 风格证据

基于整个语料（1134 个 `.cpp` 文件，约 14.6 万行）测量。除非标注为"出现次数"，计数单位均为**文件数**。本文件用于判断某条规则的约束力有多强，以及语料增长后如何重新推导出这些数字。

## 方法

1. 递归枚举所有 `.cpp` 文件。`.cph/`、`.prob`、`.vscode/`、`.idea/`、`cmake-build-debug/`、`.exe` 被排除，因为不属于源文件。
2. 使用 `Select-String -List`（匹配模式的文件）计数，因此重复出现的行不会虚增结果。标识符计数是例外，标注为出现次数。
3. **头部处理并不统一。** 大多数文件以 41 行 ASCII 艺术块开头，后接一行空行；但约 3% 的文件完全没有头部，少数文件头部较*短*。盲目跳过 42 行会悄悄吞掉这些文件里的代码。应当先检测头部：检查第 1–42 行是否全部为 `//` 或空行，只有满足时才跳过。
4. 标识符分析中已排除艺术头。头部的字形（如 `BQMDU5GQBBB7`）各出现约 1098 次，否则会主导标识符排名。
5. 使用 `-Encoding UTF8` 读取。文件是 UTF-8；按 ANSI/GBK 读取会产生类似 `//璁板繂鍖栨悳绱?` 的乱码，使注释失去意义。
6. 时代划分依据文件 `LastWriteTime`。记录的修改时间从 2025-07 平滑延续到 2026-09，没有成批聚集，因此它们是真实的写入时间，而非复制痕迹。

## 注意事项

- 计数均为文件级，除非标注为出现次数；因此一个文件中含某模式无论重复多少次都只计 1。
- `#define int long long` 使每个 `int` 都是 64 位；依赖 32 位回绕的代码会静默产生不同结果。
- `lowbit` 在当前文件中已带括号（`(x&(-x))`），但旧形式（不带括号）仍残留在约 35% 的 2026 文件及更老的文件中——在旧形式下 `lowbit(a+b)` 会展开错误。
- 时代归属假定 `LastWriteTime` 反映创作时间。逐月分布平滑支持这一点，但一个在写完很久之后被编辑的文件会被错定年代。
- 若风格再次变化，请重新生成本文件；2026-04 → 2026-06 的模板升级表明风格并非静止不动。

### 结构发现

- 交互题刷新用 **`fflush(stdout)`**（`codeforces\1044\C.cpp` 等 5 个），不用 `endl`/`cout.flush()`；输出查询行后、读入响应后各刷一次。
- 主席树孩子数组是 `ch[x][2]`（不是 `ls[]/rs[]`），版本根 `root[]`，节点计数 `tot`，插入走引用参数 `insert(int x,int &y,...)`。
- 树链剖分 dfs 序叫 `id[]`（不叫 `dfn[]`）；`dfn[]` 是 Tarjan 的领地（5 个文件）。
- 网格题网格本体是固定尺寸二维数组 `char a[505][505]`（145 个文件用固定尺寸二维数组，`vector<string>` 仅 11 个）；多状态最短路把状态并进 `dis[x][y][st]`，堆元素 `array<int,4>` + 四元组绑定。
- 几何点用 `pair<double,double>`，比较走 `dcmp`（`eps = 1e-12`）；2026 年浮点状态表升级为 `long double`（`QOJ\2026_shenzhen_Invitation\L.cpp`）。

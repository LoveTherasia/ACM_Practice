# 以本仓库的 ACM 风格撰写 C++

本仓库收录同一作者的约 1160 份比赛题解，写于 2025 年 7 月至 2026 年 10 月。有两条凌驾于其他一切之上的事实：

1. **模板近乎通用。** 97–99% 的文件共享相同的头部、头文件引入、辅助函数和 `main`。请将其视为硬性约束。
2. **作者本人的风格在 2025 与 2026 年间发生了变化。** 大括号位置、入口函数名，以及两个 `#define` 都发生了改变。请按**当前（2026）风格**书写；2025 风格已是历史，不是要模仿的变体。

从 `references/boilerplate.cpp` 开始——它是**当前**模板，逐字摘自一份 2026-09 的文件。不要凭记忆敲模板。

## 第 0 步 —— 先走思路，再动笔

写代码之前，按 `references/thinking.md` 的固定流程推理：**题面信号 → 算法族 → 数据范围定复杂度 → 该算法族的思考剧本（依次问剧本里的问题，每问都引用了作者笔记里的真实例子）→ 结论落到本文件的骨架路由**。验证（样例 → 边界 → 对拍三件套）与思路反模式也都在该文件里。

剧本问完仍没有明确路线时，查 `references/approach-library.md` 的**题型做法库**：从语料代码注释与书写过程中提炼的元策略（条件拆分、代数变形找熟悉式子、仿写模板变体、负下标偏移、拓扑式增量构造等）和 12 类具体题型的做法条目，每条都标注出处文件可直接对照。

判断题类之后才进入下面的第 1 步。不要跳过剧本直接写模板——先有朴素递推式，再有数据结构加速；58% 的题两问之内就能解决，不要过度设计。

## 第 1 步 —— 复制规范文件

逐字复制 `references/boilerplate.cpp`，只替换空的 `solve()` 函数体和被占位的全局变量。它已经包含艺术头、头文件引入、辅助函数、`int a[N]; int b[N];`、空的 `solve()` 和 `signed main()`。

不要重新手敲艺术头——那是 41 行 `//` 加一行空行，手工复制会破坏图案。也不要加 UTF-8 BOM；本仓库所有源文件均无 BOM。

`references/examples/cf1037a.cpp` 是由本技能产出的一份完整范例：它在此模板基础上解决了 Codeforces 1037A，通过了全部五个提供的样例，并且通过了第 7 步规则的 14/14 项机械检查，艺术头也与 2026 年的文件逐字节一致。可把它作为成品形态的对照参考。

## 第 2 步 —— 硬性约定（覆盖 ≥93% 的文件）

| 规则 | 规范形式 |
| --- | --- |
| 头部 | 41 行 ASCII 艺术注释块，以 `//` 开头，后接一行空行——与 `boilerplate.cpp` 完全一致 |
| 头文件引入 | `#include<bits/stdc++.h>`——`#include` 后无空格 |
| 命名空间 | `using namespace std;` |
| 整数宽度 | `#define int long long`，因此 `int` 是 64 位，`main` 必须写作 `signed main()` |
| 别名 | `#define ll long long`、`#define ull unsigned long long`、`#define lowbit(x) (x&(-x))` |
| 常量 | `const int MOD=1e9 + 7;` 与 `const int N=1e6+10;` |
| 存储 | 按 `N` 定大小的全局数组：`int a[N]; int b[N];`——绝不用局部大数组 |
| 辅助函数 | 逐字复制 `qpow`、`inv`、`lcm` |
| 随机数 | `mt19937 rng(...)` 加 `int Base = uniform_int_distribution<>(8e8,9e8)(rng);`——即使未使用也照抄 |
| I/O 设置 | `ios::sync_with_stdio(false); cin.tie(0); cout.tie(0);` 作为三条独立语句 |
| 测试用例循环 | `int t=1;`，多测时接 `cin>>t;`、单测时接 `//cin>>t;`，然后是 `while(t--) { solve(); }` |
| 入口 | `void solve()`——2026 年 881 个文件中有 867 个使用 |
| 缩进 | 4 个空格 |
| 流运算符 | 两侧不留空格：`cin>>n;`、`cout<<res<<"\n";` |
| 换行 | `"\n"`，绝不用 `endl`（仅 1% 的文件） |
| 下标 | 从 1 开始：`for(int i=1;i<=n;i++)` |
| 中点 | `int mid = (l + r) >> 1;` |
| 取模 | 每次累加后立即取模：`res = (res + x) % MOD;` |
| 整型无穷大 | `MOD * MOD`（73 个文件的标准写法）；`0x3f` 全库 0 次，`1e18` 仅 15 次 |
| 空格分隔输出 | 行内 `cout<<x<<" ";`，行尾换行 `cout<<last<<"\n";` |
| void 提前返回 | `return ;`——分号前留一个空格（218 个文件） |

## 第 3 步 —— 按 2026 风格书写，而非 2025 风格

作者在风格上经历过"时代更替"。以下数据只统计带有 ASCII 头的文件（即确定是作者本人作品）：

| 维度 | 2025（n=250） | 2026（n=881） |
| --- | --- | --- |
| 控制流的 `{` 另起一行 | 57.8% | **4.7%** |
| 控制流的 `{` 同行（K&R） | 42.2% | **95.3%** |
| 入口命名为 `Love_Hitachi_Mako` | 116 个文件 | 5 个文件 |
| 入口命名为 `solve` | 133 个文件 | 867 个文件 |
| `#define ull unsigned long long` | 0% | 98.6%（自 2026-06 起） |
| `#define lowbit(x) (x&(-x))` 带括号 | 0% | 98.6%（自 2026-06 起） |

因此，对于新代码：

- **大括号用 K&R 风格。** `void solve() {`、`for(int i=1;i<=n;i++) {`、`while(t--) {`。2025 年那些把控制流大括号另起一行的文件确实是一个更早的阶段——不要照搬。
- **入口函数是 `solve()`。** 个性化的 `Capitalized_Underscore` 命名（`Love_Hitachi_Mako`、`Himeno_Sena`）是 2025 年的习惯，2026 年已基本放弃。不要发明新名字。
- **保留 `#define ull unsigned long long` 并给 `lowbit` 加括号。** 两者都落地于 2026-04 → 2026-06 的模板升级，现已成为标准。不带括号的 `lowbit(x) x&(-x)` 是过时的形式。
- ASCII 头、`signed main()`、`cin>>` 的空格、`"\n"`、从 1 开始下标，这些在各时代间**没有**变化。

`references/style-evidence.md` 保存了全部测量数据，包括模板升级的逐月时间线。

## 第 4 步 —— 命名

- **入口。** `void solve()`。每个文件一个。
- **循环计数器。** `i`、`j`、`k`。分层 DFS：`dfs1` / `dfs2`。
- **局部变量。** `res` 累加答案，`cnt` 计数，`n` 和 `m` 是序列长度，`l` / `r` 是边界，`idx` 作为游标移动，`now` 是遍历中的当前节点，`maxvalue` / `minvalue` 是运行中的最值。
- **图。** 邻接表数组 `e[]`、`ne[]`、`h[]`，由 `idx` 遍历，用 `void add(int x,int y){ e[++idx] = y,ne[idx] = h[x],h[x] = idx; }` 构建——永远使用逗号串联赋值。
- **并查集。** `fa[]`、`sz[]`、`int find(int x)`，递归实现路径压缩。
- **线段树。** 全局 `tree[]` 加 `tag[]`/`lz[]`，配合 `push_up` / `push_down` / `addtag` / `build` / `update` / `query`。
- **命名一律为小写 `snake_case`**（`push_up`、`query_sum`、`find2`）。本语料中不存在驼峰命名。

## 第 5 步 —— 惯用法

- 直接把输入读进你要用的区间：`for(int i=1;i<=n;i++) cin>>a[i];`
- 用逗号运算符串联琐碎语句：`cin>>a[i],update(a[i]);`、`fa[i] = i,sz[i] = 1;`
- **调试输出注释掉而非删除：** `//cout<<i<<" "<<cnt[i]<<"\n";`。语料中保存着约 470 行这样的注释——这是刻意的；保留它们，不要做"清理"。
- 解释性注释极为罕见。唯一被接受的例外见 `references/approach-library.md` 末尾的注释类型学：DP 表/线段树数组上方一行语义注释、复杂推导与证明的多行注释链、按执行顺序的步骤注释、网格题方向数组的方位注释。
- 分节横幅只出现在模板文件中：`// =============== 求能异或得到的最大值 ====================`。
- `main` 中不写题目逻辑。
- 多测：保留 `cin>>t;` 处于启用状态。单测：注释为 `//cin>>t;`，同时保留 `int t=1;`。
- 排序写 `sort(a+1,a+n+1)`；降序第三参 `greater<int>()`；自定义顺序给 struct 写成员 `operator <`。**不写 lambda（全库 0 次），几乎不写 `bool cmp`（2 个文件）。**
- 取堆顶/出队/解 pair 用结构化绑定：`auto [cost,pos] = q.top();`、`auto [x,y] = q.front();`（70 个文件）。
- 字符串一律 `string`（`char s[N]` 全库 0 个文件）；拆数字用 `while(x){ ... x /= 10; }`，不用 `to_string`/`stoi`。
- 多测重置用循环重赋值（`vis[i] = 0`）或在读入循环里覆盖（`dist[i] = MOD * MOD;`），不引入 `memset(0x3f)`。

## 第 7 步 —— 收尾检查清单

1. 头部注释块存在、未被修改，恰好 42 行。
2. 同时有 `#define int long long` **和** `#define ull unsigned long long`；`lowbit` 带括号。
3. `signed main()`，绝不写 `int main()`。
4. `int t=1;` 加 `cin>>t;` 或 `//cin>>t;` 之一。
5. 入口是 `solve()`。
6. K&R 大括号——控制流的 `{` 绝不另起一行。
7. 所有输出用 `"\n"`；不用 `endl`。
8. 数组是全局、按 `N` 定大小；`vector` 不作为普通数组的替代品使用（仅 12% 的文件这样用）。
9. 4 空格缩进，`cin>>x` 两侧无空格。
10. 循环从 1 开始下标，除非算法确实需要 0 下标。
11. 不新增解释性注释；任何调试打印均已注释掉。
12. 无穷大是 `MOD * MOD`；没有引入 `0x3f`、lambda、`bool cmp`、`char s[]` 或 `to_string`。
13. 排序边界是 `sort(a+1,a+n+1)`；若写 Dijkstra，堆声明用带空格模板参数 + `greater<>`，堆顶跳过写 `if(cost > dist[pos]) continue;`。
14. 无解输出 `cout<<-1<<"\n";`（81 个文件的惯例）；网格题用全局 `dx[4]/dy[4]` + 固定尺寸二维数组，越界判断 1-based。
15. 没有引入 `struct Point`、`cross()`、`bool cmp`、`getline`、`__builtin_*` 或 `Case #` 编号。

## 反面模式

- **混搭两个时代。** 不要把 2025 年的大括号另起一行风格与 2026 年的约定混用，也不要用动漫角色名命名入口函数。全篇统一使用 2026 那一列的约定。
- **盲目照抄 `一些板子集合` 的文件。** 其中有几个根本不在作者的模板体系内：`数据结构\线段树.cpp` 是外部模板（`#include<iostream>`、制表符缩进、Allman 大括号、带空格的 `cin >>`、无 `solve()`），`数论\米勒-拉宾素性检验.cpp` 是一段光秃的外部代码片段，没有头部、没有 `main`、也没有 `using namespace std;`。另外四个数据结构文件（`线段树.cpp`、`线段树维护区间gcd.cpp`、`线性基.cpp`、`矩阵快速幂.cpp`）完全缺少艺术头。抄**算法**，不要抄文件的外壳。
- **`endl`。** 仅 1% 的文件使用；请用 `"\n"`。
- **不带括号的 `lowbit`。** 自 2026 年模板升级起已过时。
- **把"带壳"当合规。** `nowcoder\2026国庆第四场\I.cpp`（2026-10）有标准艺术头，但正文是带空格 `cin >>`、中文块注释、0-based 的外部/AI 生成风格。判断合规看正文，不看有没有头；也不要照抄这类文件。
- **撞名两对数组。** KMP 失配数组叫 `nxt[]`，链式前向星叫 `ne[]`——同一文件里两个都要用，不能互相顶替。Tarjan 的 dfs 序是 `dfn[]`，树链剖分的 dfs 序是 `id[]`——各自领域有自己的名字，不要统一。
- **交互题用 `endl`/flush 不是犯规。** `fflush(stdout);` 是交互题的标准刷新方式，是 `"\n"` 规则唯一正当的例外场景；除此之外仍一律 `"\n"`。
- **BOM 与编码漂移。** 新源文件保持无 BOM 的纯 ASCII。一些较老文件带 GBK 编码的中文注释，按 UTF-8 读取会乱码——请在 PowerShell 中用 `-Encoding UTF8` 读取它们，且不要模仿那种编码。
